# TChat 1.4.0 · 다중 파일 업로드

## 파일 다운로드·용량 안내·네이티브 화면 개선

- 파일 메시지의 저장 버튼을 누르면 Windows의 **다른 이름으로 저장** 창을 엽니다. 다운로드는 최대 512MiB이며 자동으로 파일을 실행하지 않습니다. 수신이 끝나야 목적 파일을 교체하고, 실패하면 임시 파일을 정리해 기존 파일을 보존합니다.
- 업로드는 파일당 10MiB, 최대 20개입니다. 초과 파일의 이름·크기·한도를 안내하고 정상 파일은 계속 첨부합니다. 전송 직전 파일 크기를 다시 확인하며 서버 제한 초과도 별도로 안내합니다.
- 잠금 화면은 420px 폭의 작은 창으로 전환하고 계정·암호 입력에 집중합니다. 잠금 해제 후에는 대화 창 크기와 최대화 상태를 복원합니다.
- 저장된 4자리·6자리 PIN은 모두 입력하면, 문자 암호는 입력을 잠시 멈추면 자동 검증합니다. 일치하면 버튼이나 Enter 없이 잠금을 해제합니다. 잘못된 암호의 3초 대기와 ERP 접근 검사를 유지합니다. 새 암호 설정은 확인 입력과 설정 버튼이 필요합니다.
- 대화 목록·상단 메뉴·말풍선·입력창을 평면적인 데스크톱 메신저 형태로 정리하고 웹 형태의 장식·큰 카드·그라데이션을 줄였습니다. WPF 네이티브 구조와 Windows 제목 표시줄·파일 선택 창을 사용합니다.

2026-10-28 정식 릴리스. 같은 버전의 배포 파일을 입력창 디자인 개선본으로 갱신했습니다. 운영 게이트웨이의 파일 업로드 지원도 적용했습니다. 직원 간 실제 파일 송수신 확인은 아직 수행하지 않았습니다.

## 입력창 디자인 개선

- 첨부 버튼을 클립 아이콘으로 표시하고 메시지 입력 안내 문구를 추가했습니다.
- 첨부·보내기 버튼의 높이와 간격을 맞추고 보내기 아이콘을 추가했습니다.
- 선택한 파일은 파일명과 개별 제거 버튼이 있는 카드로 표시합니다.
- 입력창 테두리·그림자·포커스 표시를 정리했습니다. 최소 창 크기와 여러 줄 입력을 검증했습니다.

이미 1.4.0을 설치한 경우 앱의 같은 버전 자동 업데이트는 실행되지 않습니다. 디자인 개선본은 갱신된 설치 EXE를 직접 실행해 적용하세요.

## 사용 방법

1. 암호화되지 않은 대화를 선택하고 입력창의 **클립 아이콘(파일 첨부)**을 누릅니다.
2. Ctrl/Shift로 여러 파일을 선택합니다. 파일당 10MiB, 한 번에 최대 20개입니다.
3. 선택한 파일 목록에서 필요 없는 항목을 **제거**합니다.
4. **보내기** 또는 Enter로 전송합니다. 텍스트가 있으면 먼저 보내고 파일을 순서대로 보냅니다.

파일만 보내기도 가능합니다. 전송 중에는 입력·추가·제거·중복 전송을 차단합니다. 성공한 파일은 목록에서 제거하며, 오류가 발생하면 남은 파일 전송을 중단합니다. 응답 유실 시 서버에는 저장됐을 수 있으므로 다시 보내기 전에 대화 기록을 확인하세요. 방을 변경하면 첨부 대기 목록을 비웁니다. 전송을 시작한 파일은 처음 선택한 방으로 전송합니다.

파일 게시물의 이름·크기와 다운로드 버튼을 대화에 표시합니다. 파일 자동 실행, 끌어 놓기, 암호화 대화의 첨부는 지원하지 않습니다.

## 서버 적용

`server/compose.access.yaml`의 접근 검사기 갱신이 필요합니다. 기존 게이트웨이는 multipart를 처리하지 못하므로 앱만 업데이트하면 전송에 실패합니다. ERP 계정 권한 확인은 파일 요청에도 유지합니다. 서버 원본 클라이언트 참조의 `Post_create` v5 / `uploadAttr: file` / `type: file` 스키마에 맞췄습니다.

## 검증

- 코어 회귀 테스트 113개 통과: 다운로드 무결성·실패 시 기존 파일 보존·임시 파일 정리·인증 필드·용량 제한 포함.
- 게이트웨이 테스트 13개 통과: 파일 스트리밍·ERP 접근 검사·초과 크기 코드 413·인라인 배포 구성 일치 포함.
- WPF 화면 검증 통과: 첨부 목록·개별 제거·대기 중 업데이트 재시작 차단·암호화 및 방 선택 해제 처리, 기본 및 최소 창 크기 렌더링.
- Windows Release 빌드 성공. NuGet 취약성 피드 접속 경고가 있어 취약성 목록 최신 조회는 완료하지 못했습니다.
- 자체 포함 설치 EXE·ZIP 생성 및 게시 파일 472개의 복사 해시 검증 완료: `dist/TChat-Setup-1.4.0.exe`, `dist/TChat-1.4.0-win-x64.zip`, `dist/SHA256SUMS.txt`.
- 운영 서버 파일 저장·두 계정 간 파일 수신은 미검증입니다.

## 운영 게이트웨이 적용 확인

2026-10-28 `tchat-access` 프로젝트를 갱신했습니다. 적용 전에는 무인증 multipart 요청이 8바이트에서 API 코드 104, 2MiB 초과에서 코드 400을 반환했습니다. 적용 후에는 두 크기 모두 세션 없음 코드 119를 반환해 파일 형식·크기 검사 통과 후 인증 단계에 도달하는 것을 확인했습니다. `/healthz`도 정상입니다. 이 검증은 실제 게시물을 생성하지 않으며 파일 저장 성공을 의미하지 않습니다.

기존 ERP 디렉터리 연결·접근 검사·healthcheck·로그 크기 제한을 보존했습니다. Compose의 인라인 실행에는 `createAccessGateway().listen(...)` 진입점이 필요하며, 테스트가 이 진입점과 실제 소스 일치를 확인합니다.
